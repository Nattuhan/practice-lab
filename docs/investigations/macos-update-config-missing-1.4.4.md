# 1.4.4のMac自動更新設定欠落

2026-10-10に通常版の更新失敗を調査し、署名済み1.4.5へ移行した。

## 原因と証拠

- インストール済み1.4.4はDeveloper ID署名・整合性が正常で、起動時更新チェックも有効。しかし`Contents/Resources/app-update.yml`が存在せず、アプリは`setFeedURL`による代替設定もしていなかった。
- 保存済みビルド履歴は`electron-builder --mac --arm64 --dir --publish=never --config.directories.output=desktop/dist/release-1.4.4`。署名前の`input-manifest.json`にも更新設定がない。
- electron-builderのPublishManagerは、MacのターゲットにDMGまたはZIPがない場合、`app-update.yml`生成処理から早期returnする。アプリだけを展開する`--dir`が欠落の原因だった。署名や公証で後から削除された問題ではない。
- 保存済み1.4.4 DMGのアプリと旧インストールの`app.asar` SHA-256はどちらも`de55c371db5d510741e27e4daf918e4ab423ec79120e8bac95fbc579894be84e`。いずれも更新設定がない。
- 公開済み`PracticeLab-1.4.4-arm64.zip`のZIP中央ディレクトリ全11,182エントリをHTTP Rangeで確認し、更新設定がないことを確認した。保存済みローカルDMGと公開DMGはイメージ自体のハッシュが異なるため、公開版の確認には公開ZIPを直接使用した。
- 従来の配布検証は署名・公証・起動だけ、通常版検査は署名と設定だけを見ていた。更新先の欠落を検出せず「自動更新可能」と報告できてしまった。

## 再発防止

- 通常MacアプリのafterPackで、ビルドターゲットに依存せず署名前に更新設定を生成する。公開先の設定から必要な公開フィールドだけを取り、認証情報はアプリへコピーしない。Dev・監査用アプリは通常版の更新先を共有しない。
- 共通検査でGitHub配布元、キャッシュ名、ホスト、安定版チャンネルを検証する。
- 通常版の診断はファイル欠落・YAML不正・配布先不正も自動更新不可とする。
- 公証済みアプリ検証は更新設定を必須にする。同じ検査をアプリ・ZIP・DMGすべてに適用し、署名・公証が正常でも欠落した配布物はCIを通さない。
- 配布準備CIは検査用Node依存関係を導入する。アプリのバージョン変更や追加Release公開は行わない。

## 検証と通常版への適用

- 欠落・不正設定・ディレクトリビルド・署名前生成・認証情報の除外を回帰テストで確認。
- 実際の`--dir`ビルドでも更新設定の生成と署名の厳密検証が成功。
- 正式署名・公証済み1.4.5を検証して通常版へ移行。今回だけは更新元1.4.4が更新先を読めないため、ユーザーの明示依頼で直接入れ替えた。旧1.4.4はユーザーの追加指示により削除した。
- 通常版1.4.5の署名・公証・Gatekeeper・バックエンド起動が正常。アプリ内で「アップデートを確認」を実行し、「現在のバージョンが最新です」と表示された。起動時更新チェックも有効。
- 保存済み音源22ファイル、動画20ファイル、パート音源80ファイルはサイズ・更新時刻が不変。解析結果41ファイルに欠落はない。通常の起動による最終オープン時刻の更新はある。
- 今回確認したのは実機での更新先読み込み・最新版確認まで。1.4.5より新しい公開版はまだないため、将来版の検出・ダウンロード・再起動適用を実行したという意味ではない。
