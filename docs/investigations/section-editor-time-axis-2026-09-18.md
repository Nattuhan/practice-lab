# 編集画面と生成結果の区切りが一致しない問題

通常画面はセクションの秒数、編集画面は小節数の比率を横座標としていた。さらに保存時はdownbeatsの配列位置から秒数を再計算していた。この3つの対応が異なるため、表示だけでなく無変更保存でも境界が移動していた。

Decisionの保存結果では、イントロ終了33.01秒が通常画面の14.91%に対し編集画面では6.20%。保存前の冒頭は0秒だが、旧保存処理は最初のdownbeatである21.02秒へ置換する。

生成されたセクション時刻を固定アンカーにする小節境界の対応表を導入した。波形、選択区間、セクション幅、目盛、ドラッグのスナップ、試聴、保存に同じ対応を使用する。編集保存後も対応表を保持し、分割や結合を繰り返すことで補間位置が動くことを防ぐ。復元時は自動解析の境界へ戻す。小節ラベルを等間隔の時刻として扱わない。

利用者の保存データは編集せず、28曲の一時コピーで無変更保存を2回行い、全セクションの開始・終了時刻が元の値と一致することを確認した。単体テストでは名称変更、境界移動、再保存、復元を確認。画面テストでは小節数と時間が比例しない曲の区切り・選択区間の位置が一致することを確認した。
