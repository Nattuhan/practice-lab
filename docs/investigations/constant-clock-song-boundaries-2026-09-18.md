# 一定拍の曲で先頭・終端の拍が欠ける解析の修正

## 再現と原因

報告対象は「じぶんROCK」。以下の曲名・時刻・拍数は調査記録であり、実行時の条件や補正値には使用しない。

- 再解析結果は167 BPMで、曲中の拍間隔は約0.36秒と一定だった。
- 音は約2.15秒から始まるが、最初の検出拍は3.26秒だった。終端側は音が続いているのに213.40秒で拍列が終了していた。
- 調査中に完了した独立再解析で、以前の終端にあった約0.54秒間隔の崩れは解消した。一方、約223秒まで続く音に対して拍が約10秒不足する症状は再現した。
- 既存の拍修復は主に両端に正しい小節頭がある区間を対象とした。先頭補完も最初の検出拍が小節頭の場合に限っていた。そのため、小節頭が後から現れる先頭と、モデルが拍列を途中で打ち切る終端を扱えなかった。

## 共通処理の変更

曲内で十分に確立した一定の拍周期と小節位相を使い、元音源が支持する範囲だけ先頭・終端の拍格子を補完する。曲名、曲ID、絶対時刻、正解拍数は参照しない。

- 先頭は、最初の32拍が一定で、小節頭が同じ4拍位相に並ぶことを確認する。音源の細かな音量境界とアタック位相から実際の開始位置を求め、最初の検出拍が小節頭でなくても拍と小節頭を遡る。
- 終端は、長い一定拍列から周期を回帰する。末尾の検出が崩れた場合は最後の信頼できる拍から置き換え、単に打ち切られた場合は最後の拍から延長する。
- リズムが続く終端では、アタックが四分・八分格子へ一致することを要求する。既存の疎い終端拍が音源へ合う本当のハーフタイムは置き換えない。
- ロングトーンやフェードでは新しいアタックがないため、連続した音量と滑らかな減衰を使って音が消える位置を求める。連続した無音を越えて後続の動画音声へ延長しない。
- 保存済みの小節位相を引き継ぎ、先頭・終端に追加した拍から小節頭とセクションの小節番号を更新する。再適用しても拍を増やし続けない。

## 検証

- 報告音源では167 BPMを維持し、583拍・146小節から613拍・154小節へ補完した。先頭は3.26秒から2.178秒、終端は213.40秒から223.149秒へ広がり、追加区間も約0.361秒間隔になった。
- 周期0.33、0.49、0.68秒と異なる開始位置で、一定拍の終端打ち切りを復元した。
- 終端だけ1.5倍間隔へ崩れる入力を一定格子へ戻した。本当のハーフタイム、無音、異なる位相、異なるテンポの終端は保持した。
- 先頭の小節頭が最初の検出拍から2拍後にある入力と、先頭・終端がロングトーン／フェードになる入力を補完した。
- ワンオク・indigo la Endフォルダーの残り8セッションを読み取り並列で検査し、全件でBPMを維持したまま終端を5〜40拍補完した。補正後の最大拍間隔は各曲の拍周期に収まり、結果保存だけは共有マニフェストの競合を避けて直列に実行した。
- 音源タイミングの対象テスト52件、Python全体292件と4件のサブテストが成功した。
