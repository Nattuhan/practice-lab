# 短小節・終盤の実機再生とテンポ選択の追加確認

前回の[8曲の再解析](eight-song-regression-2026-10-02.md)で画面ロックのため残った再生確認を、隔離したApple Silicon版アプリで追加した。前回の元音源からの解析結果と同じローカル音声・動画を使用し、通常版の保存結果は上書きしていない。今回の結果コピーは再生用であり、新規のモデル推論として数えていない。

## 確認範囲

ネイティブアプリを実際に操作して読み上げ・クリックを有効にし、速度1.00xで再生した。Bluetooth出力の表示補正は約285〜290 ms。画面状態、実機の出力時計、パート時計、シーク・ループ・再生イベントを検査した。

この環境の音声入力は非対応だった。下記は聴感や出力デバイスからの録音を確認したという意味ではない。8曲の短い区間を実際のフロント側`alignedWav`で音声化し、元のステレオPCMが全サンプル一致すること、独立に小節頭から求めた番号と音声サンプルから識別した番号が一致することを検査した。合計117発の読み上げに番号の誤りはない。

7曲では同梱バックエンドの実際のパート書き出しジョブも実行し、107発の読み上げが正しい番号になった。音声テンプレートとの最小相関は0.999001。MP3の読み上げ時刻にはミックスのリミッターによる共通の約4.966 msの遅れがある。これは実機のBluetooth遅延とは別の値。新宝島はこの隔離プロファイルに公開用パート音声がなかったため、フロントの元音源再生と出力を確認した。

最初の書き出し要求では全パートの音量を0にしたため、7ジョブが`At least one stem must be enabled`で拒否された。アプリの不具合ではなく検査入力の誤りだった。ボーカル1%、読み上げ85%に直した7ジョブはすべて完了した。微小なボーカルが混じった出力からも番号を識別できた。

## テンポ選択中に再生キーが割り込む不具合

新しい解析画面でテンポ選択にフォーカスを置いてSpaceを押すと、選択メニューを開かず背後の曲が再生を始めた。停止していた47.0959秒から、15:04:36.292 UTCの`audio-play`が発生したことを実機ログで確認した。

共通の`keydown`処理はINPUTだけを除外しており、SELECTやダイアログ内の操作でもSpaceを再生へ、左右キーをシークへ使っていた。選択欄のデフォルト操作を`preventDefault`で奪うことが原因。曲やテンポ設定に固有の例外ではない。

`playback-shortcuts.js`に共通の対象判定を置き、入力欄、選択欄、ボタンやリンク、メディア操作、編集可能な内容、開いているダイアログでは再生キーを扱わないようにした。既に別の操作で処理されたキーも重ねて使わない。Escapeのキャンセル処理と、通常の曲画面でのSpace・左右キー・速度変更は維持した。

修正版を隔離ビルドして実機で確認した。新規解析は「一定テンポ（標準）」が初期値で、「テンポ変化あり」を選択できた。その選択欄でSpaceを押すとメニューが開き、曲は00:00で停止したまま、新たな`audio-play`もない。再解析画面は保存済みの「テンポ変化あり」を引き継いだ。ダイアログを閉じると曲画面のSpaceによる再生・一時停止と右キーによる移動が使えた。ループボタンにフォーカスを置いてSpaceを押すとループだけを切り替え、曲は停止したままだった。

追加4件を含むJavaScriptの74件が成功。フロントを再生成し、ソース生成物・同梱生成物・検証プロファイルで配信する生成物のSHA-256が一致した。音声解析処理は今回変更していない。PlaywrightのE2Eは今回実行せず、対象の操作をネイティブアプリで確認した。

## 終点と通常版への反映に残る点

DECISIONの終点は、音源で拍が曖昧になる位置ではなく、モデルの拍間隔が十分に乱れる直前を基準にしている。`_unmetered_tail`の`anchor`と保存された283.92秒が一致する。モデルがもっともらしい周期を返し続ける間は早い段階の拍支持の低下を境界に反映できない。

元音源の発音を2分割・4分割の格子へ照合し、安定区間をさかのぼる案も追加で調べた。一致率は窓の置き方や細分によって変わり、目安より前のフィルでも低下する。単純な閾値で切る案は通常のフィルを早く切るおそれがあるため、コードへ採用していない。モデルの規則性だけに頼らず音源から境界を選ぶこと、最後のフィル・本当の減速・自由な終盤を分けた検証が必要。固定時刻の切断や曲専用の補正は加えていない。

通常版`/Applications/PracticeLab.app`は1.4.3で、一定テンポ・混合拍子の2モジュールをまだ同梱していなかった。解析スクリプトと既存の拍補正モジュールも検証版のハッシュと異なる。通常の保存結果にも今回の8曲の結果は反映されておらず、例えばLove so sweetは140 BPM・162小節のまま、検証結果は139 BPM・168小節。番号や小節数が一致する曲でも、別の推論結果の拍時刻を同一と扱わない。

隔離アプリの終了後に通常版本体と設定が不変である検査を通過した。追加の通常版検査もDeveloper ID署名あり、署名整合性あり、自動更新有効で終了コード0。公開、通常版の置換、バージョン変更、R2同期は実行していない。検証データと出力音声は通常データ領域の`data/work/investigations/eight-song-regression-20261002-054356/playback-verification`に保存し、Gitへ実行時資産は追加しない。
