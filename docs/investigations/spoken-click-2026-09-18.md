# 拍番号の読み上げクリック

クリック音の選択肢に「読み上げ（ワン・ツー）」を追加した。数字1〜12の短い音声を共通PCMアセットとして保持し、ブラウザ再生とパート書き出しで共有する。音声の生成元と形式は `practice_lab/assets/README.md` に記載。

番号は検出済みの小節頭で1へ戻す。4つを固定で繰り返さないので、4拍・2拍・4拍なら1,2,3,4 / 1,2 / 1,2,3,4となる。ループや途中再生も同じ曲内の番号を読む。小節頭がない区間や12を超える番号は発声せず、誤った拍子を推測して付けない。

最初の小節頭より前に解析済みの拍がある場合は、最初と次の小節頭の間で測った拍数を使い、その区間だけ番号を後ろ向きに延長する。これにより、アカペラのピックアップにも読み上げを付けつつ、楽器が入る確定済みの小節頭では1へ戻せる。最初の小節が2拍なら2拍周期を使い、小節頭が1つしかなく拍子を測れない場合は推測せず無音を維持する。「水中少女 / Aooo」の元音源から得た拍列では、ボーカル区間が3,4,1,2,3,4、楽器が入る3.07秒が1となることを確認した。曲名・時刻・固定の4拍子は実行時に参照しない。

読み上げは楽曲・パートと同じWAVの独立したチャンネルに配置する。既存クリックのマーカーチャンネルを残し、設定に応じて通常クリックか読み上げの出力を選ぶ。時間伸縮・シーク・停止を1つのメディア再生に任せ、ブラウザの音声合成の開始遅延や別タイマーによるずれを避ける。次の拍へ長い語尾が重ならないよう末尾をフェードする。

じぶんROCKの元音源から修正後の解析を通した結果に対して、142.96〜147.323秒は4拍小節、147.323〜148.05秒は2拍小節、148.05秒以降は次の小節として番号が戻ることを確認した。読み上げ番号や時刻に曲専用の分岐はない。

検証: Python279件＋4サブテスト、単体55件、従来の画面・再生36件と追加した読み上げの0.75倍速・1.25倍速2件が成功。小節の途中から切り出す番号、独立した音声チャンネルのPCM、書き出しでの1の反復位置を検証した。

## 読み上げの高さ設定と速度追従

2026-09-19、クリック音の一覧に「読み上げ」と「読み上げ（高め）」を別々に置く構成をやめ、「読み上げ」を選んだときだけ「標準」「高め」を追加表示する形へ統一した。旧`voice-high`設定は、起動時に`clickSound=voice`と`voicePitch=high`へ移行して選択を保持する。

高めの音声は3半音から5半音へ上げた。標準音声を元に同じサンプル数のまま生成するスクリプトを追加し、全12語で発音枠の長さが変わらないことを検証する。高さを保存した直後は整列音声を再生成し、曲を開き直さなくても反映する。

読み上げは楽曲と同じメディアの独立チャンネルに入るため、再生速度は楽曲と読み上げへ同時に適用される。0.75倍と1.25倍の画面テストでは、メディアの再生倍率だけでなく、連続する読み上げの実時間間隔が`拍間隔 / 再生倍率`になることを確認する。
