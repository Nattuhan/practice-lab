# Bluetooth出力に合わせた映像・表示の同期（2026-09-18）

## 確認した事実と目的

従来の `syncVideoToAudio` はWaveSurferのメディア時刻をそのまま映像へ渡し、再生時間・波形カーソル・セクション強調も出力待ち時間を反映していなかった。音楽とクリックは共通デコーダー／AudioContextを使っているため、その同期を変えずに表示側の時計を分ける。

過去の調査にはBluetooth出力の報告遅延285msがあるが、これを固定値として利用しない。今回のMacの実出力は内蔵スピーカーであり、OS照会で `coreaudio_device_type_builtin` と既定メディア出力を取得できることを確認した。今回のBluetooth機器から空気中に出た音と画面の実測は未実施。

## 仕様

- 既定は自動。MacではOSの既定メディア出力の接続方式でBluetoothを判別する。単に接続済みの機器や、通知音の出力先は判定に使わない。
- 内蔵出力は手動設定があっても補正ゼロ。USB等も自動では補正しない。判定失敗時は古いBluetooth判定を残さない。
- 出力先を約2秒ごと、ウィンドウ復帰、再生開始、機器変更通知で確認する。照会は非同期・多重実行なし・タイムアウトあり。
- 自動補正量は `getOutputTimestamp()` の出力時刻から推定する。無効な場合は `outputLatency + baseLatency` にフォールバックする。二重加算はしない。取得不能なら自動補正しない。
- 再生位置の短い履歴を保持し、遅れて聞こえる位置を映像・波形・現在時間・セクション強調・セクション編集画面の再生位置へ反映する。速度変更、停止後の出力待ち、ループ折り返しを履歴から扱う。音源・パート・クリック・ループ判定の時計は変更しない。
- 手動シークは即座に移動先を表示し履歴をリセットする。ループでは履歴を残して、実際の出力より先に表示が折り返さないようにする。曲終了から次曲への移行は出力待ち時間を待つ。
- 波形の表示更新だけにWaveSurfer 7.12.11のrendererを利用する。`setTime` 等で音源を補正しない。この内部API依存は `renderPresentationProgress` に限定し、ブラウザテストで実際のカーソル位置も確認する。
- 補正中は時間バーにアイコンを表示。ホバー／キーボードフォーカスで補正量、クリックで「再生・同期」設定を開く。自動／手動／オフ、自動補正の微調整、手動の補正量を保存する。再生設定として保存し、バックエンドの再起動はしない。
- 停止後の出力が終われば継続描画を停止する。

## 対応範囲・限界

接続方式の自動判別はMacデスクトップアプリに対応。Windowsおよび通常ブラウザの接続方式はunknownとして扱い、自動補正しない。Windowsアプリでは設定の手動補正を利用可能。ブラウザ版への設定入口の追加は今回の対象外。

OS／ブラウザの出力時刻は推定値であり、機器の内部処理や音程保持処理の誤差までは保証しない。微調整で残差を調整できる。検知には最大で照会周期とOS処理時間の待ちがある。

## 検証

`npm run test:unit` 61件、`npx playwright test --workers=2` 41件が成功。ビルド、差分検査、設定画面とツールチップのスクリーンショット確認も実施。

- 単体テスト：内蔵・Bluetooth・未知の出力、判定失敗時の解除、補正オフ、推定値のフォールバック、速度変更・停止・復帰・手動シーク・ループの履歴。
- ブラウザテスト：Bluetooth相当の286msを注入し、メディア時刻に対する表示時計／実際の波形カーソルの遅れ、アイコン、設定保存と再読み込み、内蔵出力への切替、0.5倍速を確認。
- 合成動画を用いたブラウザテスト：0.75倍速の区間ループを複数周回し、動画時刻と表示時計を記録。シーク付近を除く安定区間の差が150ms未満、停止後は50ms未満になることを確認する。テスト用動画の配信もRangeリクエストに対応させる。
- これらは報告遅延を模擬した検証であり、実Bluetooth機器でのリップシンク測定ではない。

ローカルにインストール済みのアプリへの反映、バージョン変更、リリース公開、R2同期は実施していない。
