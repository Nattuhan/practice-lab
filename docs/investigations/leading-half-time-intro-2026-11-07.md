# 後続の拍から長音イントロの半テンポ追跡を見直す

## 目的と原因

対象は「銀杏BOYZ - エンジェルベイビー LIVE 2017」の0:07〜末尾。
利用者の指摘は、長い音符で始まるイントロの追跡を、後から現れる明確な拍で
見直す仕組みが必要というもの。補間先に打音が毎回あることを要求しては、
長音イントロの数え方の誤りを直せない。

保存結果は `tempoMode=variable`、182 BPM・597拍・149小節だった。
冒頭の検出拍間隔は約0.67秒、約27秒から約0.33秒になる。
元音源からの独立した全曲推論でも、この冒頭の半密度の追跡を再現した。
本書の曲名、ID、時刻、BPMは観測値であり、実行時の条件には使用しない。

既存の `normalize_tempo_grid` は可変テンポの拍を全曲のBPMへそろえないため、
可変モードでは補間を実行しない。音源照合側の `_dominant_grid_spans` は
全曲の一定周期・位相を前提にするため、ライブ演奏の局所的な揺れを持つ今回の
冒頭は修復しなかった。全曲を一定テンポへ切り替えて回避せず、後続の拍と
イントロの局所的な追跡密度を比較する後処理を追加した。

## 共通処理

`audio_timing._resolve_leading_half_time` を既存の拍修復の前に実行する。

- 最初の持続的な約2:1の拍間隔の切り替わりを探す。後続16間隔の安定性と、
  冒頭の少なくとも8間隔の半密度を確認し、短いフィルを境界としない。
  固定の秒数や全曲のBPMでは区間を決めない。
- イントロを重ならない4検出間隔の窓で評価し、端数の末尾も追加確認する。
  長音が続く窓は、後続で確立した拍との連続性を優先する。
  長音ではない窓は、旧追跡が落としたアタックを補間した拍が説明することを要求する。
  無音には拍を新設しない。
- 少なくとも2窓かつ評価窓の80%以上に情報を要求する。
  低音と胴鳴りの交互性が元の遅いキック／スネアを繰り返し支持する場合は維持する。
  この保持判断は、後段の既存の一定時計による修復にも伝え、細かいハイハットで
  本当の遅いグルーヴを上書きする迂回経路を防ぐ。
- 冒頭の元の拍をすべて残し、隣り合う拍の中点を追加する。
  全体の周期へ再回帰しないため、ライブ演奏の速度の揺れを残せる。
  後続の拍列、全曲のBPM、利用者が選んだ可変モードを維持する。
- 後続の測定済み小節が一定の拍数を持ち、イントロの旧小節も同じ拍数なら、
  その拍数でイントロの小節頭を数え直す。最初の測定済み小節頭をアンカーにし、
  セクションの小節番号も再計算する。
- `audioTimingRepair.version=8` の `leadingHalfTime` に理由、観測した境界、
  挿入拍数、評価窓数とバックビートの票数を記録する。

近い2倍への切り替わりを無条件に実際の加速と読むのでなく、追跡密度の変更を
先に疑う設計である。一方、約2倍という比率だけで、明確な遅いバックビートまで
消さない。長音だけの音源では意図した拍の階層を完全には識別できないため、
後続との連続性を使う推定であることは限界として残る。

## 実音源の検証と反映

元WAVから分離・特徴抽出・全曲モデル推論を行い、その未補正出力を最終の
共通後処理へ通した。さらに保存済みWAVの通常の再解析サービスを実行した。
後者は既存の無加工分離WAV4本を作業場所へリンクして再利用し、特徴抽出と
モデル推論はやり直した。再解析はインストール済み追加ランタイムに、
リポジトリの解析スクリプトを渡して実行した。

両経路でイントロに37拍を追加し、182 BPM・634拍・158小節になった。
保存した再解析結果の冒頭の拍間隔は0.320〜0.355秒、中央値0.335秒。
全体のBPMと可変モードを維持し、検出開始2.23秒・終端211.83秒も維持した。
独立推論間では拍・小節頭に小さな差があり、両者が完全一致するとはしていない。
未補正モデル出力との比較では、冒頭の修復後から既存の終端停止までの拍が
そのまま残ることを確認した。最終処理の再適用でも変わらない。

通常版の対象セッション、ローカル再生用JSONとmanifestへ、再解析サービスが
生成した結果を保存した。元WAVと再利用した分離WAV4本のハッシュ不変確認は成功した。
他の結果全件のハッシュ不変確認は、利用中の「F」の `lastOpenedAt` が変わったため失敗した。
更新時刻を確認し、対象とmanifest以外で検証中に更新されたのはこの閲覧メタデータを
持つファイルだった。他曲を元へ戻す処理は行っていない。

元WAVのSHA-256は
`ccd293483170e7f77fb22ca713e3f3a83de7d36e2677ddcfb53b4274abbb05c0`。
証拠はGit管理外の `data/work/leading-octave-20261107/` に保存した。

## 回帰検証と残る範囲

- 長音だけのイントロから8ビートへ移る合成音源を、異なるテンポ・開始位置、
  短いイントロと長いイントロ、滑らかな速度の揺れで検証した。
  四分音符ごとの打音がなくても補間し、元の拍と後続の拍を維持する。
- 本当に遅いキック／スネア、ギターの細分音符を重ねた遅いグルーヴ、無音、
  1.5倍・1.25倍・0.8倍の実際のテンポ変更を保持する。
  新規・再実行の解析入口と再適用も確認した。
- 実音源の冒頭を時間方向に0.8倍・1.2倍へ伸縮し、それぞれ先頭へ0.71秒・1.37秒を
  加えた入力でも、固定BPM・固定境界を与えず37拍を回復した。
- WAVがある26セッションを読み取り専用で比較し、新処理が拍を追加したのは
  報告対象のみ。ほかの25セッションは追加しない。
- Pythonテスト539件と10サブテストが成功した。

通常版では別の曲がループ再生中だったため、対象曲へ切り替える表示・再生確認は
行っていない。クリック音声の聴感の位相、小節頭すべての正解性、冒頭2.23秒より前の拍は
今回の完了範囲に含めない。

ソースと対象の保存結果まで反映した。通常版アプリ本体・追加ランタイムの入れ替え、
バージョン変更、公開・R2同期は行っていない。通常版からの将来の再解析にも恒久的に
適用するには、修正コードを同梱したアプリへの更新が必要である。
